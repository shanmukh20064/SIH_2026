# Architectural & Implementation Decisions (ADR)

## Decision 1: Python 3.14 Environment & Dependency Selection
- **Context**: The host environment runs Python 3.14.0. Some compiled binary packages (like older psycopg2 or legacy C-extensions) may not have pre-built wheels for 3.14.
- **Decision**: Select stable, pure-python or modern C-wheel packages:
  - FastAPI + Uvicorn
  - SQLAlchemy 2.0+ (pure Python ORM mode compatible with SQLite)
  - Pydantic v2
  - PyMuPDF (`pymupdf` >= 1.24, which supports modern Python)
  - Pillow (PIL)
  - `python-multipart` for uploads
  - `pyjwt` or `python-jose` for JWT tokens
  - `passlib` with `pbkdf2_sha256` or `bcrypt` (fallback to hashlib PBKDF2 if compiled bcrypt is missing on Windows)
  - Pytest + httpx for test client.
- **Outcome**: Zero dependency headaches on Windows Python 3.14; runs fully local and fast.

## Decision 2: Local SQLite with PostgreSQL Compatibility
- **Context**: The application must run without external dependencies (no separate database server required for local hackathon demo) while maintaining production readiness for cloud deployment.
- **Decision**: Use SQLAlchemy with SQLite by default (`sqlite:///./compliance_platform.db`), enabling WAL mode and foreign key constraints on SQLite connection. Design all models with standard ANSI SQL datatypes and UUID string columns so switching to PostgreSQL only requires setting `DATABASE_URL=postgresql://user:pass@host/db`.
- **Outcome**: Seamless local single-command startup without Docker/PostgreSQL installation, fully production-ready when scaled.

## Decision 3: Document Parsing & OCR Graceful Degradation
- **Context**: Scanned documents require OCR (Tesseract). Tesseract OCR is an external binary on Windows that may or may not be installed on the host machine.
- **Decision**:
  1. Primary text extraction uses PyMuPDF (`fitz`), which extracts text streams, metadata, and coordinates with zero external binary requirements.
  2. For scanned documents (low text density), check if Tesseract is installed (`pytesseract.get_tesseract_version()`).
  3. If Tesseract is detected, perform image preprocessing (Pillow/grayscale/contrast) and extract text.
  4. If Tesseract is NOT detected, mark the document status as `MANUAL_REVIEW_NEEDED` with clear message: *"OCR binary not found on host. Document requires reviewer manual scrutiny or Tesseract installation"*, instead of crashing or pretending extraction succeeded.
- **Outcome**: Adheres strictly to the prompt requirement: *"Avoid silently treating unreadable or missing fields as verified. If OCR is unavailable, report the limitation clearly and provide setup instructions rather than pretending extraction succeeded."*

## Decision 4: Rule Engine Design & Historical Version Locking
- **Context**: Regulatory guidelines change over academic cycles. If a rule is edited in 2026, old applications from 2025 must reflect the rule state at the time of their scrutiny.
- **Decision**:
  1. The `compliance_rules` table stores a `version` integer for each rule code.
  2. When an administrator updates a rule, the version is incremented.
  3. When a validation is executed, the `validation_runs` table snapshots the exact `{rule_code: version}` dictionary in `rule_versions_snapshot`.
  4. Findings reference `rule_code` and `rule_version`.
- **Outcome**: Preserves historical compliance fidelity; eliminates risk of retroactively invalidating past audit verdicts.

## Decision 5: Non-destructive Human-in-the-Loop Review
- **Context**: An AI system cannot arbitrarily make final regulatory decisions or accuse institutions of forgery.
- **Decision**: Findings generated by the automated engine are categorized as `FLAGGED` indicators. Reviewers can update them to `CONFIRMED`, `DISMISSED`, `RESOLVED`, or `NEEDS_ADDITIONAL_EVIDENCE` accompanied by reviewer notes. The final application status transition (`APPROVED`, `DEFICIENCY_ISSUED`, `REJECTED`) is only performed by an authorized human reviewer.
- **Outcome**: Full explainability, zero hallucinated accusations, legally defensible audit trail.

## Decision 6: Frontend Architecture
- **Context**: Modern web guidance requires rich aesthetics (vibrant colors, glassmorphism, modern typography, responsive cards, micro-animations) without complex build chains that could break locally on Windows.
- **Decision**: Single-page application using modern Vanilla JavaScript, CSS custom properties (variables), Glassmorphic dark/light themes, Inter/system font stacks, and real-time fetch calls to FastAPI REST endpoints.
- **Outcome**: Zero npm/node compilation blockers; stunning instant load time and rich interactive experience.
